# GPT-5.3 Codex Spark routing

Spark is a fast Codex subscription worker inside Dickie. It is not a separate authority and it does not bypass Ringer checks.

## Use Spark for

- narrow UI component work with named file ownership;
- focused test additions and mechanical fixes;
- copy cleanup and structured inventories;
- first-pass review lanes whose claims are checked by another lane;
- large batches of independent tasks with deterministic deliverables.

## Escalate to a frontier subscription model for

- architecture or security decisions;
- work spanning several contracts or repositories;
- ambiguous evidence synthesis;
- adversarial release review;
- final production approval.

## Manifest selection

Set the task engine and model explicitly:

```json
{
  "engine": "codex",
  "model": "gpt-5.3-codex-spark"
}
```

Ringer records the exact model, harness, access class, duration, retries, checks, and verdict. A Spark task is successful only when its declared files exist and its executable checks pass.

## Cost boundary

The verified path uses Codex OAuth subscription access with metered API-key variables removed. Usage is still limited by the subscription allowance shown by Codex. Use Spark for throughput, not for meaningless extra work, and route by measured task performance rather than the remaining-usage percentage.
